# Quick Task 260805-f5m: Guard userCreatedHandler against absent settings records

## Problem

Creating a Plone site from the `imio.dms.mail:examples` profile aborted with:

```
Module imio.googleauthenticator.userdataschema, line 113, in userCreatedHandler
Module imio.googleauthenticator.helpers, line 833, in is_two_factor_authentication_globally_enabled
Module imio.googleauthenticator.helpers, line 159, in get_app_settings
Module plone.registry.registry, line 78, in forInterface
KeyError: 'Interface `...IGoogleAuthenticatorSettings` defines a field `ska_secret_key`,
          for which there is no record.'
```

No site was created. Observed 2026-08-05 by the operator while preparing the Phase 7
plan 07-04 install-order verification.

## Root cause

Four confirmed links, each read directly in the source:

1. `configure.zcml` lines 60-64 register `userCreatedHandler` as a subscriber to
   `IPrincipalCreatedEvent` at the top level of the file, with no site or layer
   constraint. ZCML subscriber registrations are instance-wide, so the handler fires
   for user creation in every Plone site in the Zope process, installed or not.
2. `userdataschema.py` line 113 called `is_two_factor_authentication_globally_enabled()`
   with no check that this add-on is installed in the current site.
3. `helpers.py` line 833 calls `get_app_settings()`, which at line 159 calls
   `registry.forInterface(IGoogleAuthenticatorSettings)`.
4. `forInterface` raises `KeyError` when the records are absent. The records are
   created only by this package's GenericSetup profile. `PluggableAuthService` notifies
   the event from inside `_doAddUser`, so the raise escaped through `addMember` and
   `imio.dms.mail`'s `create_users_and_groups` import step up to `addPloneSite`.

The other two instance-wide subscribers in the same ZCML file were checked and do NOT
share the defect: `on_process_starting` reads only an environment variable, and
`redirect_pending_2fa` returns early unless a request key is set that only this
package's PAS plugin sets — and that plugin is in `acl_users` only when installed.

## Tasks

### Task 1 — guard the handler, with a regression test

- `src/imio/googleauthenticator/userdataschema.py`: wrap the settings read in
  `try`/`except KeyError` and return without doing anything. Move the
  `api.user.get` call below the guard so the bail-out path does no lookup.
- `src/imio/googleauthenticator/tests/test_setuphandlers.py`: add
  `test_user_creation_survives_absent_settings_records`, which removes the
  `globally_enabled` record and then calls `api.user.create`, exercising the real
  `_doAddUser -> notify() -> subscriber` path rather than calling the handler directly.

**Placement decision — the guard must NOT go in `helpers.get_app_settings()`**, even
though that is the shared chokepoint all callers route through. Every other caller of
that function is reached only from an installed site: the PAS plugin (placed in
`acl_users` by `setupVarious`), the browser views (registered on this package's browser
layer), and the control panel. For those a missing record is a real fault that must
raise. Defaulting there would make `is_two_factor_authentication_globally_enabled()`
answer `False` and silently stop enforcing two-factor authentication — a fail-open
change in a security path, in a project that deliberately fails closed.

### Task 2 — record the invariant
