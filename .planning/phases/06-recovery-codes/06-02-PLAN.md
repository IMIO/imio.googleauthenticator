<objective>
Wire recovery-code issuance into enrollment, display the ten codes exactly once in the response
that generates them, and give an already-enrolled user a visible path to regenerate the whole set.

Purpose: plan 06-01 proved a recovery code can log a user in. Nothing yet *issues* codes to a
real user through the UI, and there is no way to replace a spent set. This plan closes both, and
it does so with the smallest possible new surface: one call, one `render()` override, one template,
one portal action reusing an existing availability view.

Output: `generate_recovery_codes` called on the enrollment success path, a same-response one-time
display, a `regenerate_recovery_codes` portal action, and the RECOV-01/03/06 tests.
</objective>
