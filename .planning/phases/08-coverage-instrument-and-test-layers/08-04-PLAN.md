<objective>
Close the branch-coverage gap to above 90% by writing real tests for the four weakest modules, in
order of weakness, then point CI at the coverage-gated command so the threshold actually gates.

Purpose: the corrected instrument from plan 08-01 measured 84% branch coverage pre-layer-change, and
the gap is concentrated rather than diffuse — the per-user and bulk 2FA-disable views sat at 40% and
56% with essentially no tests at all, and the control-panel save handler at 68%. These are
user-facing security-adjacent code paths, not unreachable defensive branches, which is why D-11
closes the gap with tests rather than with a coverage-exclusion pragma or a lowered threshold. Then
the gate has to live somewhere: the CI workflow hands one command string to a reusable workflow this
repo does not own, and changing that one string is the only expressible enforcement point.
Output: `bin/test-coverage -t '!robot'` exits 0 locally and runs on every push.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous HTTP request -> the per-user 2FA-disable endpoint | An unauthenticated caller reaching this view could turn off a second factor. The guard is the boundary, and until this plan it had no test. |
| manager HTTP request -> the bulk enable/disable views and the control-panel save handler | One request changes the 2FA state of every account in the site. |
| coverage number -> merge decision | The 90% threshold is a merge gate; a number produced by suppressed measurement is a gate that reports safety it did not check. |
