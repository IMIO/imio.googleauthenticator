<objective>
Move every test class in this package onto the ZSERVER-free `FunctionalTesting` layer, retire the
integration-testing layer entirely, then fix every failure the isolation change reveals.

Purpose: `IntegrationTesting.testTearDown` only calls `transaction.abort()` and stacks no per-test
storage, so an explicit `transaction.commit()` inside a test body is written straight into the
layer's shared storage and never rolled back. Six test files commit inside test bodies
(`test_challenge` 7 times, `test_token` 17, `test_reset_bar_code` 7, plus `test_helpers`,
`test_pas_plugin`, `test_setuphandlers`), and a seventh publishes through a testbrowser, which
commits too. `FunctionalTesting` stacks a fresh `DemoStorage` per test and closes it at teardown,
discarding every write including committed ones — which is why D-09 moves all of them rather than
only the seven that structurally require it. A split rule fails *silently*: an added commit in a
test left on the old layer reintroduces exactly the leak this requirement exists to close.

Output: one layer for this package, per-test isolation, and a green suite with every revealed
defect fixed and recorded.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test layer -> code under test | A test layer that leaks committed state across tests can make a broken authorization guard appear enforced. The boundary is the isolation guarantee itself. |
| revealed failure -> the fix | The choice of where to fix a revealed failure — the test's expectation or the code — is the point at which a real defect either gets closed or gets hidden. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-08 | Elevation of privilege | test-suite isolation (`IntegrationTesting` teardown aborting without discarding committed writes) | high | mitigate | Move all 16 test class attributes to the functional layer, whose per-test `DemoStorage` is stacked at `testSetUp` and closed at `testTearDown`, discarding committed writes wholesale. Retire the integration layer definition so the leak cannot be reintroduced by one attribute assignment. This is the structural fix for test-time false confidence — a lockout, replay or authorization guard that passed only because a previous test's committed state satisfied it. |
| T-08-09 | Tampering | the fix chosen for each revealed failure | high | mitigate | Per-failure classification recorded before the fix; code-side causes fixed code-side with a non-vacuity control; prohibitions in `must_haves` forbid skipping, deleting, weakening or inverting a test, and forbid re-introducing a swallowed exception or loosening a fail-closed path. Verified by an automated gate that no skip or expected-failure decorator exists anywhere in the test tree. |
| T-08-10 | Repudiation | the record of what the isolation change revealed | medium | mitigate | Task 1 deliberately commits the mechanical change without fixing anything, so the failure list is captured as evidence before any repair. STATE.md already predicted these failures; without the recorded list, a later reader cannot distinguish a pre-existing bug revealed here from a regression introduced here. |
| T-08-11 | Denial of service | suite runtime on the functional layer (a fresh `DemoStorage` stacked per test instead of per layer) | low | accept | The per-test stack is what buys the isolation; a runtime increase over the ~58s baseline is the intended cost. Recorded in the SUMMARY so a later reader sees it, but nothing here is tuned for speed at the expense of isolation. |
