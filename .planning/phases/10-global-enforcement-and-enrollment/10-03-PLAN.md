<objective>
MFA-16: with `globally_enabled` on, a user cannot turn their own second factor off. Both views that
can turn one off learn to refuse.

`browser/disable_two_factor_authentication.py` clears the flag, the seed and the reset token for
whoever calls it, with no condition at all (D-08). `browser/disable_two_factor_authentication_for_all_users.py`
does the same for every account on the site, also with no condition (D-14, D-18). Both get the same
refusal.

Purpose: this is the security control, and it lives in the views. Phase 9 established one phase ago
(BUG-08) that hiding an affordance is not a control, because a bookmarked or hand-typed URL still
works. Plan 04 hides the menu links; this plan makes the URLs refuse.
Output: a `globally_enabled` guard in both views, a new translatable refusal message, and a second
test class.
</objective>

<scope_boundary>
**D-18 is an operator-approved widening, not unplanned work.** MFA-16 as literally worded speaks
only of "a user's own second factor". Gating the site-wide un-enroll view goes beyond that wording.
The operator was offered the alternatives on 2026-08-06 — leave it and record a Future Requirement,
or delete the view outright — and chose to gate it, on the stated reasoning that shipping a refusal
which stops one user turning their own factor off while leaving a one-click "disable for everyone"
reachable makes the enforcement incoherent. It is a small change to a 31-line view and it reuses the
refusal D-08 is already writing.

**What this plan does not touch.** The `# disable_two_factor_authentication_for_users(users)` line
commented out in `browser/controlpanel.py:152` stays commented out — that is the separate, still-open
"turning `globally_enabled` off enrolls nobody out" item in STATE.md's Deferred Items, and it is not
this phase's. Refusing a mismatched `userid` at either view is also still a Future Requirement
carried over from Phase 9, deliberately out of scope. RESEARCH.md's Pitfall 3 corrects an inaccurate
claim in CONTEXT.md's Deferred Ideas — that "the disable-for-all-users path is commented out and only
logs" was only true of the `controlpanel.py` half; the standalone view is live (D-14). D-18 acts on
the live one.
</scope_boundary>

| browser -> `@@disable-two-factor-authentication` | An authenticated but otherwise untrusted request asks to remove its own second factor. Reachable by a hand-typed URL with no menu link involved. |
